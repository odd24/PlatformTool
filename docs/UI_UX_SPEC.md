# PlatformTool UI/UX 与视觉一致性规范

> 状态：重构强制规范
>
> 适用范围：`standard` 与 `engineering` 全部页面
>
> 最后更新：2026-09-24

## 1. 目标

PlatformTool 的界面应呈现为一套统一、克制、可靠的工程工具，而不是多个互不相关的功能页面集合。

最终体验必须满足：

- **简洁**：一个页面只有一个清晰主任务，避免重复入口、重复说明和无意义装饰。
- **优雅**：通过排版、留白、层级和细节体现品质，不依赖高饱和颜色、厚重阴影或复杂动画。
- **舒适**：长时间查看日志、数据、文档和媒体时不过度刺激，信息密度可控。
- **一致**：相同语义使用相同组件、颜色、间距、反馈和交互。
- **可靠**：权限、Root、串口、后台任务等状态始终可见，危险操作不会伪装成普通操作。
- **高效**：常用操作容易触达，工程数据可以快速扫描、复制、筛选和导出。

本规范是功能验收的一部分。功能正确但明显违反本规范的页面不得视为完成。

### 1.1 设计方向：Calm Expressive

本项目采用 **Material 3 Expressive 的克制表达型风格**，内部代号 `Calm Expressive`：

- 以 Material 3 Expressive 为基础，不继承现有 AppCompat 蓝绿主题。
- 通过大胆但有秩序的排版、圆润容器、空间层级和自然动效体现现代感。
- 首页、工具发现和关键完成时刻可以更有表现力；日志、串口、Console、文档等长时间工作页面保持冷静和高效。
- 采用 Material You 动态配色，同时提供全新的 PlatformTool 固定回退主题。
- 追求“现代、友好、专业”，不追求花哨、游戏化、玻璃拟态堆叠或高饱和霓虹效果。

“最新潮流”在本项目中意味着使用现代 Android 的系统能力和交互范式，而不是频繁更换装饰风格。

## 2. 设计原则

### 2.1 一屏一主任务

- 页面必须有唯一标题和一个主要操作目标。
- 同一个卡片整体可点击时，不再放置“打开”按钮制造重复入口。
- 主操作每个区域最多一个；次操作使用次级按钮、图标按钮或菜单。
- 不把教程、状态、控制和输出全部堆在同一视觉层级。

### 2.2 层级来自排版和留白

- 优先用字号、字重、间距和分组表达层级。
- 阴影只用于需要表达浮层或明显层级的组件。
- 默认卡片使用细描边或轻微色差，不使用厚重投影。
- 页面最多使用一种品牌主色；绿色、黄色、红色只表达状态语义。

### 2.3 工程信息清晰但不过载

- 对普通用户先展示结论，对工程人员提供可展开的原始数据。
- 原始值、单位、时间戳、执行后端使用等宽数字或等宽字体。
- 高频数据保持布局稳定，禁止数值变化造成控件宽度跳动。
- 状态说明必须回答“现在是什么状态”和“下一步能做什么”。

### 2.4 渐进披露

- 默认显示最常用选项；高级参数放入“高级设置”区域。
- 不可用功能显示原因和解决动作，不展示无意义的灰色控件海洋。
- Root、Bridge、系统签名等工程信息仅在相关工具中突出。

### 2.5 尊重系统和用户

- 支持浅色、深色、系统字体缩放、显示缩放和减少动画设置。
- 不强迫横屏；视频和图表确需横屏时也必须保留状态。
- 不用颜色作为唯一状态表达，必须配合图标或文字。

## 3. 视觉语言

### 3.1 Material You 色彩系统

现有 `blue_700`、`green_700` 等色阶资源不是新主题的设计前提。实现时应使用 Material Theme Builder/Material Color Utilities 从全新种子生成完整 tonal palette，并通过语义 token 消费颜色。

#### 固定回退主题

- 主题名：`PlatformTool Calm Expressive`。
- 主种子：冷静的靛紫色，设计起点建议 `#5B5BD6`，实施时允许在视觉评审中微调。
- 中性表面：带极轻冷色倾向的 graphite/neutral palette，而不是纯灰或大面积纯白/纯黑。
- Secondary 和 tertiary 从 Material 色调算法生成，用于层次和少量表达，不在业务页面随意增加“第二品牌色”。
- Success、Warning、Error、Info 使用扩展语义色，独立于动态品牌色，确保工程状态含义稳定。
- 浅色和深色均由同一 token 系统生成，不手工拼凑两套无关配色。

#### 动态配色

- Android 12+ 默认支持 Material You Dynamic Color，并在设置中允许用户切换到固定 PlatformTool 主题。
- Android 11 及以下使用固定回退主题。
- 动态色只能替换 Material ColorScheme 角色；成功、警告、错误、日志级别和图表数据系列必须保持可辨识语义。
- 无论壁纸产生何种色板，均需验证 Primary、Container、Surface 和文本对比度。

#### 必须使用的 Material 语义角色

```text
primary / onPrimary / primaryContainer / onPrimaryContainer
secondary / onSecondary / secondaryContainer / onSecondaryContainer
tertiary / onTertiary / tertiaryContainer / onTertiaryContainer
surface / surfaceContainer* / onSurface / onSurfaceVariant
outline / outlineVariant
error / onError / errorContainer / onErrorContainer
inverseSurface / inverseOnSurface / inversePrimary
```

规则：

- 业务布局不得直接引用十六进制颜色或旧色阶名。
- 页面内高强调色面积要克制，主要依靠 container 层级而不是纯色铺满。
- 页面内状态色总数应尽量不超过三种。
- 正文和背景对比度至少满足 WCAG AA；普通正文目标不低于 4.5:1。
- 图表不得只靠红绿区分数据系列，应同时使用线型、点型或标签。
- 日志级别颜色在深浅主题和动态色下都要可读，不能铺满高饱和背景。

### 3.2 排版

中文使用系统无衬线字体；拉丁字符和数字优先采用系统支持的现代可变字体/Roboto Flex。日志、Shell、串口、Raw 数据和结构化数值使用系统等宽字体。

| 样式 | 字号 | 建议字重 | 使用场景 |
|---|---:|---:|---|
| Display | 36sp | 600 | 首页欢迎标题和关键 Hero，少量使用 |
| Page title | 28sp | 600 | 页面主要标题 |
| Section title | 20sp | 600 | 区域标题 |
| Card title | 16sp | 600 | 工具卡、数据卡标题 |
| Body | 15sp | 400 | 正文和主要说明 |
| Label | 14sp | 500 | 按钮、输入标签、筛选项 |
| Supporting | 13sp | 400 | 次要说明、状态细节 |
| Data mono | 13sp | 400/500 | 日志、串口、原始值 |
| Caption | 12sp | 400 | 时间戳、来源、脚注 |

规则：

- 正文行高为字号的约 1.4～1.6 倍。
- 不使用纯粗体堆叠层级；同一区域最多两个明显字重。
- 用户字体调至 1.3 倍时，关键文本不得截断或相互覆盖。
- 实时数值应使用制表数字或稳定宽度容器。

### 3.3 间距和尺寸

全局使用 4dp 基础网格：`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48`。

- 手机页面水平边距：16dp。
- 宽屏/平板页面水平边距：24～32dp，内容最大宽度按页面类型限制。
- 卡片内部边距：16dp；紧凑数据卡可使用 12dp。
- 同组控件间距：8dp；不同内容组间距：16～24dp。
- 页面大区块间距：24～32dp。
- 最小点击区域：48dp × 48dp。
- 单行主要按钮高度：48dp；紧凑工具栏按钮仍需保留 48dp 点击区域。

禁止出现任意且相近的间距值，例如同一页面混用 13dp、14dp、15dp、17dp。

### 3.4 圆角、边界与阴影

- 页面卡片：20～24dp 圆角，使用 Material 3 Expressive shape scale；默认依靠 Surface Container 层级而非描边和阴影堆叠。
- 输入框、选择器、状态块：12～16dp 圆角。
- 主要按钮：完整胶囊或高圆角；次级按钮和筛选 chip 遵循同一 shape family。
- 模态弹窗/Bottom Sheet：顶部或整体 24dp 圆角。
- 浮层才使用明显阴影；列表卡片禁止层层高 elevation。
- 同一层级组件必须采用相同圆角和边界，不允许各页面自行发明样式。
- 表达性形状只用于工具卡、选择态和关键时刻；终端输出、表格、长文档容器保持规整。

### 3.5 图标

- 统一使用同一套 Material 风格线性图标。
- 默认 24dp，工具分类图标可使用 28dp；图标容器推荐 40dp。
- 同一语义始终使用同一图标，例如播放、导出、连接、停止、Root。
- 不使用 emoji 作为正式功能图标。
- 纯图标按钮必须有 content description 和可见 tooltip/说明能力。

### 3.6 当前 token 实现映射

- Compose token 统一由 `core/ui/PlatformTheme.kt` 和 `PlatformTokens.kt` 暴露；业务 Composable 不复制颜色、字号、间距、形状或动效常量。
- XML 迁移层通过 `Theme.PlatformTool` 的 Material 3 Bridge 和 `pt_*` 语义资源消费同一套浅深色角色；旧颜色名只作为待迁移页面的兼容别名，不得被新页面引用。
- 固定回退主题以 `#5B5BD6` 建议种子生成并经对比度调整，实际 primary 为浅色 `#4F4CB7`、深色 `#C4C0FF`；Success、Warning、Info 使用独立扩展角色，不随动态品牌色变化。
- 响应式断点固定为 Compact `<600dp`、Medium `600～839dp`、Expanded `≥840dp`，通过 Material 3 Adaptive 的窗口信息触发重组，不依据设备型号或方向。
- 稳定动效时长为 150ms、200ms、250ms；XML 和 Compose 均从集中 token 读取。

## 4. 页面骨架

### 4.1 应用首页

推荐结构：

```text
Edge-to-edge Top App Bar：PlatformTool     搜索  设置

欢迎标题 / 简短设备状态摘要

最近使用（存在记录时显示）

分类筛选：全部  媒体  文档  设备  工程

工具网格或列表
┌──────────────────────────────┐
│ [图标]  工具名称        [能力徽标] │
│         一行用途说明              │
└──────────────────────────────┘
```

首页规则：

- 整张工具卡可点击，删除卡片内重复的“打开……”按钮。
- 手机单列或双列由可用宽度决定；不得把文字压缩到难以阅读。
- 卡片描述最多两行，名称最多两行。
- `Root`、`Bridge`、`系统签名`使用克制的小型能力徽标，不使用大面积警告色。
- 不可用工具仍可进入说明页或弹出原因，但要明显区别于可用状态。
- 搜索覆盖名称、说明和关键词；无结果时提供清除搜索操作。
- 首页不在功能尚少时强制加入底部导航；只有形成三个以上稳定顶层目的地后才评估。
- 工具卡可使用轻度形状变化、容器色和共享元素过渡形成 Expressive 体验，但不得造成卡片尺寸跳动。

### 4.2 标准功能页面

```text
Top App Bar：返回  页面标题                 页面操作

状态/权限提示（仅需要时）

主要内容

次要设置或高级选项

必要时的固定主操作区
```

- 返回位置、标题位置和页面操作保持一致。
- 页面标题不重复出现在内容区。
- 关键状态靠近相关控制，不把所有反馈都用 Toast 表达。
- Toast 仅用于轻量、短暂且无需操作的反馈；可恢复错误使用内联提示或 Snackbar。

### 4.3 工程控制台页面

适用于日志、串口、Console：

```text
Top App Bar

连接/执行状态条：后端、身份、目标、状态

主要参数（常用）                 高级设置

输出区域（占据剩余空间、等宽字体、可选中）

底部操作：输入/发送/运行     停止或连接
```

- 输出区优先占据可用空间，不被大量设置挤压。
- 连接、运行、暂停、停止使用一致的动词和图标。
- Root 身份始终可见，但不使用持续闪烁或大面积红色。
- 危险操作使用确认弹窗，并明确显示命令、目标和影响。

### 4.4 数据监测页面

适用于传感器、电池和 FPS：

- 顶部显示整体采集状态和开始/停止控制。
- 关键数据使用 2～3 列自适应数据卡；小屏自动单列。
- 单位作为次级文本，不与数值同等强调。
- 原始数据放在可展开的“Raw/详细信息”区域。
- 曲线颜色、图例、坐标和当前值使用一致映射。
- 暂停显示和停止采集是不同状态，文案和图标必须区分。

### 4.5 媒体页面

- 媒体库使用缩略图/图标、标题、时长和最近进度的统一条目。
- 当前播放项具有清晰但克制的选中态。
- 音频 mini player 固定在内容底部，进入完整播放页时视觉连续。
- 视频控制层在无操作后淡出，触摸恢复；动画保持短且不干扰观看。
- 空媒体库直接提供“选择文件”和“选择目录”两个清晰入口。

### 4.6 文档阅读页面

- 阅读内容是视觉主体，工具栏默认简洁，可按需隐藏。
- 搜索、目录、书签、阅读设置采用一致入口。
- 阅读背景、字号、行距可调，但预设选项数量要克制。
- PDF/图片缩放操作保持系统手势习惯。
- 加载大文档时显示真实进度或分页占位，不使用无限阻塞转圈掩盖失败。

## 5. 组件规范

### 5.1 按钮层级

| 类型 | 使用限制 |
|---|---|
| Primary | 当前区域唯一主操作，例如“开始记录”“连接” |
| Secondary | 与主操作并列的非主动作，例如“扫描”“重新授权” |
| Tertiary/Text | 低强调操作，例如“清除筛选”“查看详情” |
| Destructive | 删除、终止或高风险操作；只在确有破坏性时使用红色 |

禁止同一区域出现两个视觉权重相同的 Primary 按钮。

### 5.2 状态提示

统一状态组件至少覆盖：

- `Info`：说明或普通能力提示。
- `Success`：完成、已连接、已授权。
- `Warning`：功能受限、需要 Bridge/Root、结果可能不完整。
- `Error`：执行失败、权限拒绝、文件失效。
- `Progress`：扫描、连接、导出、加载。

组件包含图标、简短标题、可选说明和最多一个主解决动作。错误信息不得只显示异常类名。

### 5.3 表单

- 标签位于输入框上方或使用一致的 Material outlined field，不混用多套形态。
- 单位、示例和限制使用 supporting text。
- 校验错误显示在字段附近，并保留用户输入。
- 开关只用于立即生效的二元状态；需要确认或提交的选项使用复选框/选择器加按钮。
- 高级参数默认折叠，但折叠区标题应显示是否使用了非默认值。

### 5.4 空、加载和错误状态

- 空状态说明为什么为空，并提供一个最可能的下一步。
- 首次加载使用骨架或轻量进度；短于约 300ms 的任务避免闪烁加载控件。
- 局部失败只替换对应区域，不让整个页面失效。
- 重试必须保持用户已经填写的参数和筛选条件。

### 5.5 列表与滚动

- 长列表使用 RecyclerView/惰性列表，行高和分隔方式统一。
- 不嵌套同方向滚动容器。
- 列表筛选、排序和总数使用固定位置，刷新时不跳动。
- 日志、串口等高频列表默认跟随到底部；用户手动上滚后暂停自动跟随并显示“回到底部”。

## 6. 响应式布局

| 可用宽度 | 布局策略 |
|---|---|
| `< 600dp` | 单栏为主，必要时双列紧凑数据卡 |
| `600～839dp` | 双栏工具网格，表单与结果可并排 |
| `≥ 840dp` | 限制内容最大宽度；列表-详情或控制-输出双栏 |

- 不简单地把手机界面拉宽填满平板。
- 日志、串口、文档适合在宽屏使用主从或左右分栏。
- 横屏时优先增加信息并列，而不是仅减少垂直空间。
- 折叠屏和多窗口以实时可用宽度为准，不依赖设备型号。
- 使用 Window Size Class/Material 3 Adaptive 决策布局，不用设备型号或固定方向分支。
- 出现多个稳定顶层目的地时，使用 NavigationSuiteScaffold 在 Navigation Bar、Rail 等形态间自适应。
- 列表-详情和控制-输出场景优先采用 Material 3 Adaptive 的 canonical scaffold。

### 6.1 Edge-to-edge 与系统栏

- 全应用采用 edge-to-edge，正确处理状态栏、导航栏、显示缺口、IME 和手势区域 insets。
- Top App Bar、Bottom Bar、浮动操作和滚动内容分别消费正确 inset，禁止重复 padding。
- 关键按钮和文本不得被透明系统栏、三键导航栏或键盘遮挡。
- 系统栏图标明暗随当前 Surface 自动切换，不固定为单一模式。
- 视频等沉浸页面允许隐藏系统栏，但必须可通过标准手势恢复。

## 7. 动效和触觉

- 标准过渡建议 150～250ms，使用系统自然缓动。
- 动画用于说明状态变化和空间关系，不做持续装饰动画。
- 高频数值更新不使用逐项动画。
- 尊重系统动画缩放/减少动态效果设置。
- 成功、切换、连接可使用轻触觉；错误和危险操作使用更明确但不过度的反馈。
- 不使用闪烁表达日志活动、Root 状态或正在记录。

## 8. 文案规范

- 标题使用名词或明确任务，例如“串口”“电池记录”，避免营销式长标题。
- 按钮使用动词，例如“连接”“开始记录”“重新授权”“导出”。
- 同一动作全局使用同一个词，不混用“打开/启动/进入”。
- 错误文案采用“发生了什么 + 可能原因 + 可执行下一步”。
- 不把技术异常堆栈直接展示给普通用户；工程详情可复制或展开。
- 权限说明必须解释功能用途，不使用泛化的“应用需要权限”。

## 9. 无障碍与舒适度

- 普通文本对比度至少 4.5:1，大号文本至少 3:1。
- 所有关键操作可通过键盘、方向键或无障碍焦点访问。
- 图标、图表状态和颜色标记提供文本替代。
- 支持至少 1.3 倍字体且无关键信息截断；关键流程应测试更大字体。
- 连续日志和 Raw 数据默认字号不得过小，并允许复制。
- 深色模式不是简单反色；黑色媒体页与普通深色 Surface 分开处理。
- 危险色只用于危险语义，避免用户长期处于视觉警戒状态。

## 10. 主题和组件实现约束

- 新应用壳、首页和新页面采用 Jetpack Compose + Material 3；既有 XML 页面在迁移期允许通过 Activity/Fragment 继续运行。
- 页面按阶段迁移，不以一次性重写全部 UI 为前提；但完成迁移的页面不得继续以 AppCompat 主题作为视觉基础。
- 使用 Material 3 Expressive 稳定 API；确需实验性组件时封装在 `core:ui`、记录 API 风险并提供可替换实现。
- 使用 Compose Material 3 Adaptive 的稳定版本构建响应式页面；不得为了追逐最新版本直接依赖未经评估的 alpha。
- 颜色、排版、形状、间距通过集中 token/style 暴露，业务页面不得复制常量。
- 优先提供 `AppTheme`、`AppTopBar`、`ToolCard`、`StatusBanner`、`MetricCard`、`EmptyState`、`ErrorState`、`EngineeringOutput` 等通用组件。
- 迁移期 XML 与 Compose 必须映射到同一 token，不允许形成两套视觉系统。
- 迁移期 XML 必须通过 Material 3 Bridge 主题映射同一语义 token，不得继续扩展旧 AppCompat 主题。
- 深色方案必须真正实现 Material 3 dark ColorScheme；不得继续引用 Light 主题伪装成深色模式。
- Theme 负责窗口背景，页面根布局不重复绘制相同不透明背景。
- 页面只能通过语义 token 使用状态色，禁止直接引用旧色阶名称。
- 动态配色开关、主题模式和对比度选择属于全局设置，不由单个页面控制。

## 11. 现有页面迁移优先级

1. Compose Material 3 应用壳、全新主题、颜色、排版、形状 token 和通用状态组件。
2. 首页：删除重复按钮，改为数据驱动工具卡。
3. 日志、Console、串口：建立统一工程页面骨架。
4. 音频、视频：统一媒体列表和播放控制。
5. 传感器、电池、FPS：统一数据卡、Raw 详情和图表样式。
6. 文档阅读：基于同一主题新增，不再创建独立视觉体系。

迁移单页时必须同时处理浅色、深色、字体放大、小屏和宽屏，不留到最后统一补救。

## 12. UI 验收清单

每个页面完成前至少检查：

- [ ] 页面只有一个清晰主任务和唯一页面标题。
- [ ] 使用统一 token，没有业务层硬编码颜色、字号、圆角或任意间距。
- [ ] 同层级组件的样式、对齐和文案一致。
- [ ] 没有重复入口或同一区域多个 Primary 操作。
- [ ] 加载、空、失败、权限不足、不支持和成功状态完整。
- [ ] 浅色和深色模式均可读，没有突兀色块或对比不足。
- [ ] 320dp 小屏、常规手机、600dp+ 宽屏布局无重叠和异常拉伸。
- [ ] 字体 1.3 倍时关键内容和操作不被截断。
- [ ] TalkBack/键盘焦点顺序合理，图标按钮有说明。
- [ ] 动画克制，并遵循系统动画设置。
- [ ] 日志、列表和实时数据长时间运行时界面稳定、不跳动、不卡顿。
- [ ] 危险、警告和成功颜色只表达对应语义。
- [ ] 截图与已通过评审的参考页面/基准图进行对比。

## 13. 视觉评审门禁

为了避免“每个页面单独看都可以，组合起来却矛盾”，采用以下门禁：

1. **基础组件评审**：主题 token 和核心组件通过后，功能页面才能批量迁移。
2. **首个参考页面**：首页、一个标准工具页和一个工程密集页作为三类视觉基准。
3. **双主题截图**：每个迁移页面至少保留浅色、深色截图；响应式页面增加手机和宽屏截图。
4. **差异检查**：新增页面与三类参考页面比较排版、间距、圆角、颜色和状态组件。
5. **整体验收**：版本发布前串行浏览全部入口，检查是否存在独立风格页面、重复交互或冲突文案。

自动截图测试可在基础 UI 稳定后引入，但不能代替真机视觉评审和无障碍检查。
